Access Review for Jira

Access Review runs the periodic user access review (recertification) of Jira that SOX IT general controls, ISO 27001 (A.5.18) and SOC 2 (CC6.2, CC6.3) ask for. It takes a snapshot of every project role and every person in it, directly or through a group; flags deactivated accounts, privileged people with no recent activity in the project, privileged roles granted to large groups and public projects; lets project leads and Jira administrators keep or revoke each line (revoking removes the access in Jira immediately, as the reviewer); and exports the decisions as audit evidence.

Setup

  1. Install the app in Jira and open Apps → Access Review as a Jira administrator.
  2. Name the review, optionally limit it to some project keys, and select Take snapshot and start review. On large sites the snapshot runs in the background for a few minutes; the page updates by itself.
  3. Project leads see the projects they lead; Jira administrators see everything. Choose Keep or Revoke for each line. Nobody can certify their own access, and keeping access with a high-severity finding needs a written justification.
  4. Evidence generates a CSV with one row per line: decision, reviewer, time, justification and the removal result.
  5. Settings: which role names count as privileged, the dormancy window (default 90 days) and the group size that is flagged.
  6. Rovo: choose the agent Access Auditor and ask "Which privileged access looks risky?". The agent is read-only. The same tools are available through MCP.

Privacy policy

Last updated: 17 November 2026

Access Review runs entirely on Atlassian Forge ("Runs on Atlassian"). It has no servers of its own and sends no data outside Atlassian.

  • What the app reads: projects, project roles and their members, group members, whether accounts are active, project permission schemes (to detect public projects) and, for people in privileged roles, a count of the work items they changed in that project during the dormancy window.
  • What the app changes: only when a reviewer chooses Revoke, it removes that person or group from that project role, using the reviewer's own permissions. It never changes group membership.
  • What the app stores: the review snapshot (names, account IDs, roles), the decisions with reviewer, time and justification, the removal results and the settings, in Forge storage on your site. Starting a new review keeps a short summary of the previous one.
  • Sharing: none. No analytics, no third-party services, no outbound network access, and no language model is called by the app itself.
  • AI: the Rovo agent and MCP tools return the same facts the page shows; the language model is Atlassian Rovo, operated by Atlassian under your Atlassian agreement.
