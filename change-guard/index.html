Change Guard for Jira

Change Guard checks every planned change before it is approved: another change on the same service at the same time, the same implementer booked twice, a change freeze, a high-risk change outside the maintenance window or raised at short notice, and a missing backout or test plan. It gives each change a verdict (Blocked, Needs review, Clear to approve), shows the next 14 days as a calendar, and can block the approval transition until the change is safe.

Setup

  1. Install the app in Jira and open Apps → Change Guard. By default it checks open changes ([System] Change) whose planned end is today or later; change the JQL in Settings.
  2. Services come from the change's components and its Affected services field. Planned start, Planned end, Change type, Change risk, Backout plan and Test plan are found by field name.
  3. Change freezes: record them the Jira Service Management way, as a change of type Freeze Period with the affected components, or add them in Settings.
  4. Set the maintenance window and timezone for high-risk changes in Settings.
  5. To enforce it, a Jira admin adds the validator Change Guard: safe window before approval to the transition that sends a change for approval. It blocks only Blocked changes and fails open if the app is unavailable.
  6. Rovo: choose the agent Change Advisor and ask "Which changes collide in the next 7 days?". The agent is read-only. The same tools are available through MCP.

Privacy policy

Last updated: 17 November 2026

Change Guard runs entirely on Atlassian Forge ("Runs on Atlassian"). It has no servers of its own and sends no data outside Atlassian.

  • What the app reads: change work items in scope (summary, status, created date, components, assignee, planned start and end, change type and risk, backout and test plans, affected services) and the list of Jira fields, with the permissions of the user viewing them. The workflow validator reads the same as the app.
  • What the app changes: nothing. It has no permission to edit work items; the validator only allows or blocks a transition.
  • What the app stores: its settings (JQL, freezes added in Settings, maintenance window, timezone, notice periods) and a cache of field ids, in Forge storage on your site. No personal data.
  • Sharing: none. No analytics, no third-party services, no outbound network access, and no language model is called by the app itself.
  • AI: the Rovo agent and MCP tools return the same facts the page shows; the language model is Atlassian Rovo, operated by Atlassian under your Atlassian agreement.
